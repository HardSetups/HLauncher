# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**HLauncher** (1.0.0-alpha.x, released on GitHub) — player-friendly, server-friendly Minecraft launcher. Electron + React/Vite, launch core on `minecraft-launcher-core` (MCLC). UI is Turkish-first with full TR/EN i18n. Repo: `HardSetups/HLauncher` (public). See `ROADMAP.md` for status, `CHANGELOG.md` for history, `docs/GELISTIRME.md` for the 2-developer workflow (branching, QC gate, release procedure — FOLLOW IT).

## Commands

```bash
npm run dev              # Vite + Electron (wait-on gates Electron until Vite is up)
npm run build            # Build frontend with Vite (injects CSP in prod via plugin)
npm test                 # unit (tests/unit.test.cjs, sync) + services (tests/services.test.cjs, async, local HTTP + mock API)
npm run test:integration # REAL network: loader installs, server manifest e2e — run before releases
npm run test:e2e         # vite build + real Electron via playwright-core against dev/mock-api (temp APPDATA, shell.openExternal stubbed)
npm run mock-api         # HardSetups API mock on 127.0.0.1:4000; use with HL_API_BASE=http://127.0.0.1:4000 npm run dev
npm run lint             # ESLint (browser rules src/, node rules electron/ + tests/ + scripts/ + dev/)
npm run dist             # Build + NSIS Windows x64 installer → release/
npm run dist:dir         # Build + unpacked dir (faster, for QA)
npm run release          # package + verify (add `-- --publish` to upload to both GitHub repos, see Release)
```

## Machine Notes

- `ELECTRON_RUN_AS_NODE=1` may be set system-wide on some dev machines (it is on the original one). It makes `require('electron')` return a path string. Dev therefore runs `node launch-electron.js` (unsets it) instead of `electron .`, and `main.cjs` has a relaunch guard at the top. Harmless on machines without the variable — never remove either.
- Prefer cloning OUTSIDE OneDrive/Drive-synced folders (file locks break builds).

## Architecture

**Dual-module:** `src/` is ESM/React, `electron/` is CommonJS (`.cjs`). Root `package.json` has NO `"type": "module"` — intentional.

**Main process (`electron/`):**
- `main.cjs` — relaunch guard, single-instance lock, `no-sandbox` when packaged, window (opaque `backgroundColor`, min 980×640, bounds/maximized persisted in store as `windowBounds`), security handlers (`setWindowOpenHandler` deny + `will-navigate` guard → https opens in system browser), all IPC handlers. Renderer data goes through `sanitizeSettingsPatch`/`sanitizeServers` (store.cjs) before writing.
- `launcher.cjs` — launch orchestration: resolve instance → install loader → ensure Java → account auth → MCLC. JVM presets (`balanced|lowram|zgc|custom`), QuickPlay for 1.20+, `--server/--port` for older. Crash detection: non-zero exit + not user-stopped → `game-crashed` event.
- `lib/paths.cjs` — data root `%APPDATA%\.hlauncher` (auto-migrates `.hardsetups`/`.thehardcraft`); instance dirs (`default` plays in root for backwards compat, others in `instances/<id>`)
- `lib/store.cjs` — atomic JSON settings store (`config.json`): settings/account/servers/activeInstanceId/windowBounds; exports the IPC sanitizers (pure, tested)
- `lib/http.cjs`, `lib/download.cjs` — all network I/O: redirects (https→http downgrade BLOCKED), timeouts, SHA1/SHA256 verify, 3 retries, contact User-Agent (Modrinth requires it)
- `lib/zip.cjs` — adm-zip with OWN zip-slip guard (adm-zip's read side does NOT sanitize `../` — proven by test)
- `lib/java.cjs` — required Java by MC version (≤1.16→8, 1.17-1.20.4→17, else 21); find (bundled→Mojang→vendors→system) or download from Adoptium with SHA-256
- `lib/instances.cjs` — profile registry (`instances.json`), CRUD, `managedFiles` + `announcements` tracking, `lastPlayed` (set by `launch-game`), `iconUrl` (modpacks), `getContentDir`. Renderer writes go through `sanitizeInstancePatch` (whitelist: name, mcVersion, loader, ram, serverAddress — tested)
- `lib/loaders/` — `optifine.cjs` (BMCL API + manual official-jar fallback), `fabriclike.cjs` (Fabric+Quilt via meta profile JSON), `forge.cjs` (Forge/NeoForge installer jar → MCLC `forge` option; NeoForge needs MC 1.20.2+, experimental)
- `lib/modrinth.cjs` — legacy mod install used by server manifests + performance preset (sodium, lithium, ferrite-core, immediatelyfast, entityculling); pure `computeUpdates` (tested)
- `lib/content.cjs` — per-profile content for `mod` / `resourcepack` / `shader` (dirs `mods`, `resourcepacks`, `shaderpacks`). Disable = rename to `<file>.disabled` (Modrinth App convention). `listContent` hashes files (SHA-1, cached by path+size+mtime) and enriches with Modrinth title/icon/version; `listEntries` is the network-free variant. Modrinth search for all 4 types (+ `modpack`), install with required deps (mods only), `installModpack` (download .mrpack → `mrpack.importMrpack` → new profile with `iconUrl`), update check/apply (apply only accepts `https://cdn.modrinth.com/` URLs). IPC: `content:*` + `modpack:install`, all return `{ok, ...}`. Long operations take a `taskId`; their progress events (`mod-progress`) carry it so the renderer's download panel updates the right row
- `lib/mrpack.cjs` — .mrpack import → new instance (path-traversal-safe)
- `lib/servermanifest.cjs` — fetch/validate/apply `hlauncher.json` (schema in docs/SERVER-MANIFEST.md); syncs managed mods, persists announcements on the instance
- `lib/accounts.cjs` — Microsoft via msmc (refresh token encrypted at rest with Electron safeStorage/DPAPI, `enc:` prefix, plaintext fallback+migration) + offline; `getMclcAuth()` for launch, `getMinecraftToken()` for the skin API (refreshed Minecraft session cached in memory 30 min). **msmc must stay in `dependencies`** — devDependencies are not packaged, Microsoft login would break in the installer
- `lib/skins.cjs` — local skin library (`%APPDATA%\.hlauncher\skins`: PNG + index.json, dedup by SHA-1, PNG must be 64×64 or 64×32 — tested) + Minecraft Services API for Microsoft accounts: profile (active skin/capes returned as data URLs because textures.minecraft.net has no CORS), upload skin (multipart, variant classic/slim), reset, set/hide cape; import a player's skin by name via Mojang public API. IPC `skins:*`, all `{ok, ...}`
- `lib/news.cjs` — launcher news from `news.json` in the `HardSetups/HLauncher-releases` repo via GitHub raw (30min cache, stale fallback, sanitized)
- `lib/updater.cjs` — electron-updater state machine (`checking|downloading|ready|uptodate|error|dev`) streamed to renderer on `updater-status` (with version, percent, plain-text release notes); checks 8 s after start then every 3 h, `setEnabled` follows the `checkUpdates` setting live; `checkNow`/`installNow` (silent quitAndInstall + relaunch). Prerelease versions (`-alpha.N`) automatically follow Pre-release GitHub releases. Renderer: download-panel row while downloading, `UpdateModal` once per version when ready (restart blocked while a game runs), TopBar "update ready" pill
- `lib/errors.cjs` — error → friendly Turkish message; `lib/logger.cjs` — electron-log → `logs/hlauncher.log`; every line passes through `lib/redact.cjs` (masks `--accessToken`, Bearer, JWTs, refresh/device codes, license keys — MCLC prints the full launch command incl. the token). Never log secrets around it; add new secret field names to `redact.cjs` instead
- `lib/discord.cjs` — Rich Presence (client ID constant; silently disabled if invalid/absent; gated by `settings.rpcEnabled`)

**HardSetups portal (`electron/services/`, in progress — branch `feature/hardsetups`):** integration with the HardSetups site/API. The contract lives in the HardSetupsWeb repo (`docs/api/launcher-api.md`, owned by the HardSetupsWeb side — send objections there, don't edit that repo). Stages C1–C5 done against contract v1.7 (mock + real local API); the live API (v0.8.10) only serves §11 by-license until the web side releases.
- `api.cjs` — the ONLY HardSetups HTTP client: contract headers (`X-HL-Version`, `X-HL-Device` = random install id in store `installId`, UA, Accept-Language) go only to the API host; `{error:{code,message,details,requestId}}` → `ApiError` (show `requestId` as "Destek kodu"); 401 `ACCESS_TOKEN_EXPIRED` → one single-flight refresh + one retry; `DEVICE_REVOKED`/`REFRESH_TOKEN_INVALID` → sign out; 426/503 → `outdated`/`maintenance` events; redirects disabled. Base URL `HL_API_BASE` (http only for localhost in unpackaged dev)
- `hsession.cjs` — device-code login (RFC 8628: PENDING / SLOW_DOWN +5 s / DENIED / EXPIRED), single-flight refresh, new refresh token persisted BEFORE use, early refresh at 80% TTL. Pure; `session-file.cjs` = safeStorage-encrypted `hardsetups-session.json` (never written if encryption unavailable)
- `portal.cjs` — main-side coordinator: config (`minVersion`, maintenance, `linkHosts`/`downloadHosts`), login flow, `/me`, server-given links. Renderer only gets `publicState()` — never tokens/deviceCode. IPC `portal:*`, events `portal:state|login|session`
- `downloader.cjs` — verified downloads: https + host allowlist incl. every redirect hop, `.part` + Range resume, sha256/sha512 + size, one retry on mismatch, `refreshUrl` for expired signed URLs, AbortSignal, `runQueue` (≤4 parallel). No API headers/tokens to CDNs
- `offline.cjs` — offline envelope (Ed25519, canonical JSON identical to HardSetupsWeb `packages/contracts` — only `signature` is stripped, `kid` stays), embedded prod key `ed1` only (never trust keys from the API), clock-rollback guard. Contract vectors in `tests/fixtures/`
- `installer.cjs` — INSTALL/UPDATE/REPAIR are ONE `syncProduct`: validate manifest (all paths via safepath, every file hashed) → skip files whose on-disk hash already matches → download to `.hl-staging/dl` → extract ONLY `extract` prefixes (zip-slip/size guarded) → commit: managed dirs (`mods/`) become exactly the manifest set (old managed files deleted, user jars moved to `mods/.yedek/`), licenseConfig merged, `hl-manifest.json` written last. Steps before commit never touch the instance. `saves/`, `options.txt` etc. are never touched
- `licenseconfig.cjs` — flat-map MERGE into the mod's own `config/hardsetups/ayarlar.json` (never overwrite; backup → tmp → read-back verify → rename; corrupt file kept as `.bozuk-<time>`); values never logged
- `library.cjs` — `/library` + signed offline envelope persisted in `hardsetups-library.json`; `launchCheck`: online ACTIVE, else envelope + clock guard (negative cache age = rolled-back clock → not fresh)
- `bylicense.cjs` — "Lisans anahtarım var" (§11): uses the response's `install` when present (v1.4), else the §11.1 table; adds Fabric API from Modrinth if the archive lacks it; picks newest stable Fabric satisfying mods' `depends.fabricloader` when the server doesn't pin one. Key-installed products have NO launcher gate (mod SDK checks)
- Managed instances: id `hs-<folderName>` (prefix reserved; user profiles get `p-`), `origin:'hardsetups'`, pinned `loaderVersion`, `quickPlayWorld` (→ QuickPlay singleplayer); mcVersion/loader not editable from the renderer; deleting one = uninstall with world backup to `<data>/yedekler`. `launch-game` runs `portal.launchCheck` first. UI: `LibraryPage` (rail "HardSetups")
- v1.5 `dependencies` (Modrinth) are resolved by `bylicense.resolveDependencies`: exact `version_number` + loader + MC version, no guessing — the server never puts Modrinth files in `files[]`
- C3 (in `portal.cjs`): `home` (ETag/304, ≤ every 5 min, 1 min on focus, unknown `action.type` dropped, dismissed announcements in store), `product`, `quote`/`purchase` (balance only; `Idempotency-Key` fixed per quoteId so double clicks = one order), `notifications`/`markNotificationsRead`. UI: `PortalPage` (tabs Vitrin / Kütüphanem + wallet chip + `NotificationsBell`), `StoreFeed` (empty sections never rendered, no placeholder content), `ProductView` + purchase modal, `ProductCard`, `Markdown` (safe subset, raw HTML never rendered, links → `portalOpenUrl`)
- `imagecache.cjs` — server images ONLY via `hlimg://c/<base64url>` (privileged scheme registered before ready): main checks `imageHosts`, no redirects, ≤5 MB, magic-byte sniff, disk cache with stale fallback. Renderer: `imgSrc(url, imageHosts)` / `toImageSrc`; `InstanceIcon` routes HardSetups icons through it
- `report.cjs` — "Sorun bildir" (§10): files (launcher log, instance `logs/latest.log`, newest crash report) collected AND re-collected at send time in main, sanitized (`redact` + user path anonymization), ≤5 files / 10 MB, multipart via `api` `raw` body; consent checkbox unchecked by default. `ReportModal` from Settings and the crash modal
- "Bu sürümde neler var": `src/utils/changelog.js` bundles CHANGELOG.md (`?raw`); shown once per version after an update (store `lastSeenVersion`), never on first install
- Offline envelope keys: prod `ed1` embedded; unpackaged + local API only also trust the contract test key and `HL_DEV_OFFLINE_KEYS="kid:raw32b64url,…"` (several keys per kid)
- `dev/mock-api/server.cjs` — dependency-free API mock (mirrors real L1/L2 behaviour, scenarios via `POST /__mock/scenario`, local Modrinth/Fabric-meta fakes for `HL_EXTERNAL_BASE`)
- Contract v1.7 (L3/L5): `home.coupons` (signed-in only, PERCENT/FIXED, unknown type dropped) shown in `StoreFeed`; campaign/announcement links outside `linkHosts` arrive wrapped as `https://hardsetups.com/cikis?…` (open as-is, never follow `u` yourself); report errors `REPORT_DISABLED`/`TICKET_DUPLICATE`/`TICKET_OPEN_LIMIT`/`ATTACHMENT_REJECTED`/`ATTACHMENT_LIMIT` (v1.7.1; v0.9.0 sends >5 files as `ATTACHMENT_REJECTED` + `reason: tooManyFiles` — keep both)/`PAYLOAD_TOO_LARGE` mapped in `ReportModal` (subject 5–200, message 10–20 000)
- `telemetry.cjs` — usage counters (§15): counted ONLY when `config.features.telemetry === true` AND `settings.telemetryConsent === true` (default off, Settings row); aggregated per (type, product), flushed every 30 min and on quit (≤3 s, only if something is pending); request is `anonymous` (no token, no `X-HL-Device`). Launch/launch_failed/crash are counted in `main.cjs` from the `launch-game` reply channels; install/install_failed in `portal` (validation/precondition errors and wrong keys not counted)
- Config 404 (`/v1/launcher/*` not deployed, e.g. live v0.8.10) → `publicState().accountAvailable === false`, login/home throw `PORTAL_UNAVAILABLE` ("henüz açılmadı"); config is retried every 5 min. Without config, the production base falls back to `cdn.hardsetups.com` for download/image hosts so §11 by-license works
- Updater feed (§12) is ON since alpha.7 (bridge release, user decision): `updater.cjs` `UPDATE_SOURCE = 'hardsetups'` → generic `api.hardsetups.com/v1/launcher/update/<stable|beta>`, headers `X-HL-Device` + `X-HL-Version`, latest.yml 404 = up to date. Releases reach players only when the user uploads the exe in the panel (Admin › Lisanslar › Launcher › Sürümler). `nsis.differentialPackage: false` (server serves no blockmap). No code signature yet → no `publisherName` check; add both when a certificate exists (never disable afterwards)
- Security hardening (alpha.7 audit): navigation is always blocked (state router; dropped local .html can't get the preload bridge), packaged builds ignore `NODE_ENV`/`HL_API_BASE`/`HL_SCREENSHOT`, DevTools + default menu off when packaged; `sanitizeSettingsPatch` validates VALUES (javaPath must be java/javaw, no UNC; `customJvmArgs` rejects `-javaagent`/`-agentpath`/`-XX:OnError`/`@file`/`-cp`… — `jvmArgsFor` filters again at launch); server manifests https-only; `launch-game` resolves the profile in main before the license gate; server-sourced links open only against the server's `linkHosts`; `pickFile` requires hex sha256 + integer size; archive/mrpack extraction checks real vs declared size (zip bombs); mrpack downloads only from Modrinth-format hosts with sha1; `ErrorBoundary` around pages; CSP `img-src` limited to hlimg:/data:/cdn.modrinth.com/minotar/crafatar
- Shared libs: `lib/safepath.cjs` (ALL server-provided relative paths go through `safeJoin`), `lib/links.cjs` (link/download host allowlists), `lib/semver.cjs`, `lib/compat.cjs` (sandbox fallback)

**Renderer (`src/`):** instance-centric, Modrinth-App-like. `App.jsx` owns state + a tiny router (`view = {page: home|instance|browse|servers|settings|account, id?, tab?, instanceId?, type?}`) and the launch state (`launchingId` / `runningId`, one game at a time); boots from `store:all` IPC (one-time migration from legacy `thc_*` localStorage keys exists). `i18n.jsx` = provider + full TR/EN dicts (`t('key', {params})`); backend progress arrives as `{key: 'be.*', params}`. Components: `Rail` (home/browse/servers, instance icons sorted by lastPlayed, +new, settings, account; fixed-position JS tooltip because the instance list scrolls), `TopBar` (breadcrumb + running status/stop + window buttons), `HomePage` (jump back in rows with Play, library grid, aside: account/servers/news/Discord), `InstancePage` (header with Play, tabs Mods/Resource packs/Shaders/Settings), `ContentList` (two-phase load: local list first, then Modrinth metadata; toggle/remove/update; `mutation` ref guards stale responses), `BrowsePage` (Modrinth search per type, target-profile picker, "installed" marks, modpack → new profile), `ServersPage` (live status, "play with which profile" menu), `SettingsPage` (label/desc left, control right rows), `CreateInstanceModal`, `InstanceSettings` (card sections: loader cards, version, RAM global/custom with slider+ticks+recommended marker+system-RAM warning, auto-connect server picker), `AccountPage` (3D stage with animations, account card, skin library with 2D previews, apply/reset skin, capes; offline accounts can use the library but not apply), `SkinViewer3D` (single WebGL instance; skin/variant/cape/animation update in place), `SkinPreview2D`, `DownloadBar` (floating bottom-right, rows per task + game launch), `VersionMenu` (loader + searchable versions; `hideLoaders`, `allowLatest` → null = always latest; measures the nearest `.page-scroll`/`.modal` to open up/down), `AccountPanel`, `Onboarding`, `Modal` (left-aligned dialog, Escape/backdrop close), `tasks.jsx` (`TaskProvider`/`useTasks().runTask(meta, taskId => ipc)` — app-wide tasks that survive navigation; use it for any install/import, never local component state), `ui.jsx` (`InstanceIcon` = Modrinth icon or deterministic symmetric 5×5 pixel identicon from the profile id, `Switch`, `Menu`, `EmptyState`), `icons.jsx`. Preload `on*` subscriptions RETURN an unsubscribe function — always return it from the effect.

**HardSetups account gate (alpha.7, user decision):** the launcher is unusable without a HardSetups account. `App.jsx` renders `AuthScreen` (full window: "Giriş yap" / "Kayıt ol" → device code; `portalLoginStart({register:true})` opens the verification page with `yeni=1`) instead of the shell while `!portal.signedIn`, and a short boot splash while `portal` is still null. A stored session opens offline; only logout / `DEVICE_REVOKED` / `REFRESH_TOKEN_INVALID` return to the gate. View logic is pure in `src/components/auth/authView.js` (tested); the device-code flow is shared via `auth/useDeviceLogin.js` (AuthScreen + HardSetupsCard). Onboarding (accent → Minecraft account → RAM) runs after login.

**Design identity (do not regress to "AI generic"):** the theme identity is `hardsetups:kiremit` — single source `docs/tema/tema.json`, rules in `docs/tema/KIMLIK.md` (in-game guide for mods: `docs/tema/oyun-ici/`). Graphite layers (`--bg` frame, `--surface` content, `--raised*` cards) with depth instead of flat fills: `--app-bg` (soft vertical gradient, faint accent light top-left, vignette, ~2.5% grain), cards with a top light line + `--shadow-card`; calm, never neon/glowing text/rainbow. ONE accent (user-chosen, default Kiremit `#A52B12`, list in `src/utils/accents.js`) for primary actions / selected state; accent as text/icon uses `--accent-text` (lightness-clamped, readable on dark for any accent); derived accent tokens live on `.app-shell` so they follow the user's choice. No uppercase letter-spaced labels, sentence-case copy. Signature: "bevel" corner — `corner-shape: var(--shape)` (round bevel round bevel) on buttons/inputs/cards/icons (Chromium 139+, Electron 39 OK; plain rounded fallback); pixel identicons for profiles; custom nav icon set in `icons.jsx` (square caps, one filled "pixel" per icon via `--px`, accent when active); lucide for utility icons (CSS forces square caps on `svg.lucide`). Chakra Petch only for h1 page titles / profile names; UI text is Segoe UI Variable. Play button: solid accent with a thin hard bottom inset shadow. Use CSS tokens in `index.css`, not hex. NO emoji as icons; `prefers-reduced-motion` respected.

**Launch model:** there is no global Play — you pick a profile (home rows/cards, profile page, or a server's "play with" menu). Launching sends `{instanceId, serverIp}` (serverIp = explicit server or the profile's `serverAddress`); main marks `lastPlayed` + `activeInstanceId` — everything else (account, RAM, Java, JVM args) is resolved in the main process from the store. Null `mcVersion` means "latest release" and is resolved main-side everywhere (a silent-failure bug in alpha.1 taught this).

**Packaged-app gotchas (do not remove):** fuses `runAsNode:false`, NODE_OPTIONS/inspect off, ASAR integrity + only-load-from-ASAR, cookie encryption (package.json `electronFuses`) + ELECTRON_RUN_AS_NODE relaunch guard; Chromium sandbox is ON — on machines where a child process dies with STATUS_BREAKPOINT in the first 30 s, `lib/compat.cjs` persists `compat.noSandbox` and relaunches once (the alpha.1–5 unconditional `no-sandbox` is gone; `HL_NO_SANDBOX=1` forces it); all browser permissions denied except clipboard write; opaque window; `vite.config.js` ignores `release/` in watch; CSP injected only at build (dev needs HMR inline scripts).

## Testing / QC (gate before every push)

- `npm run lint && npm test` always; `npm run build` after renderer changes; `npm run test:integration` before releases
- i18n key consistency: every `t('...')` key and every backend `key: 'be.*'` must exist in BOTH dicts in `src/i18n.jsx` (unit test enforces the `be.*` side)
- IPC error contract: handlers return `{ok:false, error}` (never throw across IPC for user-triggerable paths); renderer handlers must catch — no silent failures

## Release (summary — full procedure in docs/GELISTIRME.md)

Bump version (`npm version x.y.z-alpha.N --no-git-tag-version`) + CHANGELOG entry → push main, CI green → push tag `vX.Y.Z-alpha.N` (CI only builds + keeps an artifact) → `npm run release -- --publish` (scripts/release.cjs: dist, verify latest.yml sha512 vs exe, SHA256SUMS, upload as Pre-release to BOTH `HardSetups/HLauncher-releases` — the public binaries-only repo that alpha.6+ installs update from — and `HardSetups/HLauncher`, which pre-alpha.6 installs still poll). Token comes from `git credential fill`, never printed. News to players: `news.json` in the HLauncher-releases repo (keep the root copy here in sync until this repo goes private).
